# Architecture

```
                          ┌─ Host(sw65-$DOMAIN_BASE) → sw65 :80  (dockware 6.5.8.17)
Browser ─:80→ Traefik ────┼─ Host(sw66-$DOMAIN_BASE) → sw66 :80  (dockware 6.6.7.0)
                          └─ Host(sw67-$DOMAIN_BASE) → sw67 :80  (dockware 6.7.2.2)
```

One Docker Compose project (`devbox`) runs a Traefik proxy plus the three
`dockware/dev` instances on a shared `web` network. Traefik publishes `:80`
(storefront/admin traffic) and `127.0.0.1:8080` (dashboard, reach it via an SSH
tunnel — see [operations.md](operations.md)). The shop containers publish no
host ports at all; they're only reachable through Traefik.

## Hostnames
Each instance is served at `swXX-$DOMAIN_BASE` (hyphen-joined), matched by a
Traefik `Host(...)` rule and set as that container's `APP_URL`. E.g.
`DOMAIN_BASE=twint-dev` → `sw65-twint-dev`, `sw66-twint-dev`, `sw67-twint-dev`.

## Basic auth, with an API bypass
All three instances sit behind Traefik HTTP basic auth (`BASIC_AUTH_USER` /
`BASIC_AUTH_PASSWORD` in `.env`, hashed into `devbox/auth/htpasswd` by
`up.sh`). `/api` (JWT) and `/store-api` (sw-access-key) authenticate
themselves, so each instance also has a second, higher-priority router
(`swXX-api`) matching `Host(...) && (PathPrefix(/api) || PathPrefix(/store-api))`
with no auth middleware, pointed at the same backend service. Net effect: the
storefront and `/admin` prompt for basic auth; `/api` and `/store-api` do not.

## Why these choices
- **Traefik reverse proxy** — only the proxy publishes ports; shop containers
  are routed by Host header over the shared `web` network. This is what lets
  all three versions run at once (the legacy `infra/` setup collided on
  `80/443/3306`). Scales to more versions by adding a service + labels; the
  proxy is also the only place TLS will need to be added later (see
  [dns-tls.md](dns-tls.md)).
- **Traefik v3.7** — required. Docker Engine 29 dropped support for the old
  Docker API version (1.24) that Traefik ≤3.5 negotiated; with an older
  Traefik the Docker provider silently fails to read container labels, so no
  routers register and every instance 404s. See
  [troubleshooting.md](troubleshooting.md).
- **dockware/dev all-in-one** — Apache + MySQL + Shopware in one container per
  version. Simplest thing to route and to run `bin/console` against; matches
  the legacy demo setup.
- **Full-filesystem persistence per instance (`swXX_html` + `swXX_db`)** — on
  first `up`, an empty named volume mounted over a populated image path makes
  Docker copy the image's data in, so dockware's pre-installed Shopware (code
  + DB) is seeded and then persists across recreates. All config, the
  Composer-installed plugin, uploaded media, and the DB live inside these two
  volumes — there is no separate media volume. Trade-off: a seeded volume pins
  that instance's Shopware code to the image it first saw — see
  [operations.md](operations.md) → Upgrading a Shopware version.
- **Composer VCS delivery** — `deploy.sh` runs `composer require` of the
  plugin from the GitLab repo inside each container, authenticating with
  http-basic (username + token) against both the plugin's GitLab host and the
  private `twint-ag/sdk` host. Each instance resolves the plugin and its deps
  into its own `vendor/` for its own PHP version, fully isolated; all
  instances run the same deployed branch. Deploys are reproducible from a
  pushed GitLab branch, not a developer's working tree — see
  [deploy.md](deploy.md).

## Files
- `compose.yaml` — proxy + three instances, `swXX_html`/`swXX_db` volumes, `web` network.
- `bin/_lib.sh` — env loading, instance map (`resolve_targets` → `RESOLVED_TARGETS`), compose wrapper.
- `bin/{bootstrap,up,down,deploy,provision,logs,shell}.sh` — see [README.md](../README.md) table.
- `.env` (gitignored) — see [.env.example](../.env.example).
- `auth/htpasswd` (gitignored, generated by `up.sh`) — Traefik basic-auth credentials.
- `logs/` (gitignored) — one timestamped file per `deploy.sh` run.
